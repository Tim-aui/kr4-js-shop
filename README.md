# kr3-responsive-shop — адаптивный интернет-магазин видеокарт

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Дисциплина: «Фронтенд и бэкенд разработка».

## Описание

Проект — многостраничный HTML/CSS-сайт учебного интернет-магазина видеокарт
«ПослеМайнинга». За основу взят проект **КР №1** (`kr1-html-css-shop`), а не
Bootstrap-проект КР №2: вся адаптивность написана вручную на медиазапросах,
Flexbox и CSS Grid, без готовых фреймворков.

В КР №3 сайт адаптирован под экраны от 360px до 1440px, изображения переведены
на `srcset`/`sizes`/`<picture>` с форматами AVIF и WebP, исправлены проблемы
доступности. Проверка Lighthouse: **Accessibility 100** на всех проверенных страницах.

## Подключение стилей и viewport

На каждой странице в `<head>`:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<link rel="stylesheet" href="css/style.css">
<link rel="stylesheet" href="css/responsive.css">
```

`responsive.css` подключается **после** `style.css`, чтобы правила медиазапросов
переопределяли базовые стили при одинаковой специфичности.

## Адаптивные решения

- добавлен отдельный файл `css/responsive.css`;
- применён подход **Mobile First**: в `style.css` описана раскладка для телефона,
  а `responsive.css` только расширяет её через `@media (min-width: …)`;
  старые медиазапросы `max-width` из КР №1 удалены;
- точки перелома: **480 / 600 / 768 / 1024 / 1280 / 1440px**;
- **навигация**: на телефоне — кнопка «Меню» (бургер), от 768px — строка ссылок
  (Flexbox с переносом), от 1440px — логотип и меню в одну строку;
- **hero-блок**: на телефоне текст и картинка в колонку, кнопки во всю ширину;
  от 480px кнопки в строку; от 1024px — Grid в две колонки «текст | изображение»;
- **сетка карточек** (CSS Grid): 1 колонка → 2 (600px) → 3 (1024px);
  на главной 3 колонки, в каталоге рядом с фильтром 2, от 1280px — 3;
- **карточки**: фиксированная высота картинки 180px заменена на `aspect-ratio: 4/3`,
  кнопка на телефоне во всю ширину, `min-width: 0` не даёт длинным названиям
  распирать колонку;
- **каталог и боковой фильтр**: Grid-каркас `grid-template-areas`; на телефоне фильтр
  над товарами и свёрнут в `<details>`, на 600–1023px поля фильтра в две колонки,
  от 1024px — боковая колонка 260px с `position: sticky`;
- **страница товара**: фото над описанием на телефоне, две колонки от 768px;
- **таблица характеристик** обёрнута в `.table-wrapper` с `overflow-x: auto` —
  прокручивается только таблица, а не страница;
- **таблица сравнения** (новая): на телефоне каждая строка становится карточкой
  (подписи колонок из `data-label`), от 600px — обычная таблица `min-width: 640px`
  с прокруткой внутри обёртки;
- **форма заявки**: Grid — 1 колонка на телефоне, 2 колонки от 600px,
  комментарий/товар/согласие на всю ширину; поля высотой 44px и `font-size: 16px`
  (iOS не зумит страницу при фокусе); кнопки на телефоне в колонку с отступом;
- **контакты**: информация и форма обратной связи в колонку, от 768px — рядом;
- **модальное окно**: `width: min(100% - 16px, 560px)` и `max-height: 100dvh - 16px`
  с прокруткой — не вылезает за экран на маленьком телефоне;
- **от 1440px** контейнер расширен с 1100 до 1280px;
- **отсутствие горизонтального скролла**: перенос длинных слов (`overflow-wrap`),
  `min-width: 0` у grid-элементов, таблицы в обёртках, плюс страховка
  `overflow-x: clip` (не ломает `sticky`, в отличие от `hidden`).

## Responsive images

- базовое правило `img, video { max-width: 100%; height: auto; }`;
- исходные фото переименованы латиницей (пробелы и скобки в именах ломают `srcset`)
  и нарезаны на несколько ширин: 320/500px для маленьких исходников
  и 320/640/1000px для больших;
- **карточки товаров** — `srcset` + `sizes`: на телефоне ~100vw, на планшете ~50vw,
  на desktop 340px; браузер сам выбирает файл (проверено во вкладке Network:
  на 360px грузится `-320`, на 430px и шире — `-500`/`-640`);
- **hero** — `<picture>` с **art direction**: на телефоне квадратный кадр
  (`hero-mobile-*`), от 768px — широкий (`hero-wide-*`);
- **форматы AVIF + WebP**: в `<picture>` на главной и странице товара первым идёт
  `<source type="image/avif">`, запасной вариант — WebP;
- у всех `<img>` указаны `width`/`height` (нет скачков вёрстки, CLS = 0),
  у картинок ниже первого экрана — `loading="lazy"`, у главной — `fetchpriority="high"`;
- `product.js` для выбранного товара собирает `srcset` из списка ширин.

## Доступность

- добавлена **ссылка пропуска** «Перейти к основному содержимому» (skip-link)
  на всех страницах, `<main id="main" tabindex="-1">`;
- **видимый фокус** `:focus-visible` для всех интерактивных элементов
  (раньше не было у чекбоксов, `select`, `summary`); в тёмном hero — жёлтая обводка;
- проверены **`label`** у всех полей; подсказка формата телефона связана с полем
  через `aria-describedby`; ошибки помечаются `aria-invalid="true"`, фокус
  переводится на первое неверное поле;
- проверены **`alt`** у изображений: осмысленные названия товаров,
  у декоративной иконки на `success.html` — `aria-hidden="true"`;
- **контраст**: белый текст hero лежал на белом фото — теперь на тёмной плашке;
  затемнены `--color-muted` (#666 → #595959), зелёный бейдж «Новинка»
  (#168a2f → #12712a, был ниже 4.5:1), рамки полей формы;
- **семантика**: один `h1` на каждой странице, логичный порядок заголовков,
  `nav` с `aria-label`, `aria-current="page"` у активного пункта меню и в крошках,
  `th scope` в таблицах, `<address>` в контактах, телефон и почта — ссылки `tel:`/`mailto:`;
- ссылки «Подробнее» и кнопки «Заказать» дополнены скрытым текстом с названием
  товара (`.visually-hidden`) — для скринридера ссылки не одинаковые;
- **мобильное меню**: `<button>` с `aria-expanded` и `aria-controls`,
  при открытии фокус на первый пункт, закрытие по `Esc` с возвратом фокуса,
  клик вне меню закрывает; без JavaScript меню показано обычным списком;
- **модальное окно** на `<dialog>` + `showModal()`: фокус внутри окна, `Esc`,
  фон недоступен; добавлены закрытие по клику на фон и возврат фокуса на кнопку
  «Заказать»; `aria-labelledby`/`aria-describedby`;
- таблицы в обёртке с прокруткой — `role="region"`, `aria-labelledby`, `tabindex="0"`
  (прокрутка стрелками с клавиатуры);
- **ARIA только по необходимости**: роли `table/row/cell` у таблицы сравнения —
  потому что в карточном режиме `display: block` стирает табличную семантику;
- `role="status"` на сообщении об успешной отправке;
- области нажатия кнопок, пунктов меню и полей — не меньше 44px;
- `prefers-reduced-motion`: отключаются плавная прокрутка и анимации.

Проверка выполнена в Lighthouse (режим Mobile) для страниц
`index.html`, `catalog.html`, `order.html`, а также `product.html` и `contacts.html`.

| Страница | Performance | Accessibility | Best Practices | SEO |
|---|---|---|---|---|
| index.html | 100 | 100 | 100 | 100 |
| catalog.html | 100 | 100 | 100 | 100 |
| order.html | 100 | 100 | 100 | 100 |
| product.html | 100 | 100 | 100 | 100 |
| contacts.html | 100 | 100 | 100 | 100 |

Что исправлено по результатам проверки:

- **Best Practices 96 → 100**: ошибка 404 в консоли из-за отсутствующей favicon —
  добавлен `images/favicon.svg`;
- **Performance каталога 86 → 100**: CLS 0.28 — фильтр сворачивался скриптом
  `defer` уже после отрисовки, и товары «прыгали» вверх. Теперь сворачивание
  выполняет маленький inline-скрипт сразу после `<details>`, до первой отрисовки.

Отчёты сохранены в папке `lighthouse/`:
`accessibility-report.png` (главная), `accessibility-<страница>.png` и полные
HTML-отчёты `accessibility-<страница>.html`.

Lighthouse не заменяет ручную проверку: дополнительно вручную пройдены страницы
клавишей Tab, проверены меню, фильтр, модальное окно и формы с клавиатуры.

## Самостоятельные доработки

- мобильное меню-бургер с анимацией в крестик, `aria-expanded`, закрытием по `Esc`,
  клику вне меню и переходу по ссылке, возвратом фокуса, работой без JS;
- сворачиваемый фильтр каталога на `<details>` (свёрнут на телефоне, всегда раскрыт
  и sticky на desktop) без скачка вёрстки;
- таблица сравнения с карточным представлением на мобильном;
- несколько вариантов responsive images: `srcset`/`sizes`, art direction через
  `<picture>`, форматы **AVIF и WebP**;
- доступное модальное окно (клик по фону, возврат фокуса, название товара в окне);
- новая форма обратной связи на странице контактов, работающая без JavaScript;
- кнопка «Оформить заявку» на странице товара сразу подставляет товар в форму;
- улучшенный контраст, skip-link, области нажатия 44px, `prefers-reduced-motion`;
- Lighthouse 100 во всех категориях на пяти страницах;
- подробный README и публикация на GitHub Pages.

## Контрольные вопросы — краткие ответы

- **Mobile First** — сначала пишем стили для самого узкого экрана, затем добавляем
  правила для широких через `min-width`. Поэтому `min-width` и удобен:
  каждый следующий медиазапрос только дополняет предыдущий.
- **viewport** — без него мобильный браузер рисует страницу шириной ~980px
  и уменьшает её, медиазапросы не срабатывают.
- **srcset** — список файлов с их шириной (`320w`), **sizes** — какую ширину картинка
  займёт на экране; по ним браузер выбирает файл. **picture** — разные изображения
  или форматы по условиям (`media`, `type`).
- **Горизонтальный скролл страницы** — ошибка, потому что часть контента скрыта
  за краем экрана, и страница «болтается» вбок при прокрутке пальцем.
